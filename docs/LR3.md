# ЛР3 — реализация Travel Planner

Документ описывает сделанный код и помогает заполнить бланк. Исходные DOCX не изменены. Результаты ниже относятся к локальному проекту; публикация в GitHub и заполнение бланка не выполнялись.

## Таблица 2.1: данные

Файл: `frontend/front/src/data/trips.js`. Массив: `trips`, 10 объектов. Категории: Город, Море, Горы, Природа. Функция: `getTripById(tripId)`.

| Поле | Тип | Пример | Назначение |
| --- | --- | --- | --- |
| id | number | 1 | key и маршрут |
| title | string | Путешествие в Париж | Название, поиск, сортировка |
| country | string | Франция | Страна и поиск |
| city | string | Париж | Город и поиск |
| category | string | Город | Группировка и фильтр |
| days | number | 5 | Длительность, сортировка |
| budget | number | 480000 | Бюджет в тенге, сортировка |
| startDate | string | 2026-11-02 | Дата начала, сортировка |
| description | string | Прогулки вдоль Сены… | Описание и поиск |
| scene | string | city | Имя локальной иллюстрации |
| departure | object | date, time, from, to, timezone | Данные вылета |
| events | array | day, time, title, place | Расписание событий |

Все поля отображаются на подробной странице: `scene` задаёт иллюстрацию, `id` — номер путешествия, вложенные объекты — вылет и список событий. Время вылета имеет отдельный часовой пояс, время событий относится к месту посещения.

## Таблица 3.1: TripCard

Props: `id`, `title`, `country`, `city`, `category`, `days`, `budget`, `startDate`, `description`, `scene`. State отсутствует. Ссылка «Подробнее» ведёт на `/trips/${id}`. Полный список событий и вылет показываются только на подробной странице.

## Шаг 5: сценарии ID

- `/trips/1` — информация о Париже, бюджет, дата, 5 событий и вылет.
- `/trips/999` — «Путешествие не найдено».
- `/trips/abc` — «Путешествие не найдено».
- `/несуществующий-адрес` — страница 404.

## Шаг 6: пропуски в учебном примере

1. `useState` — хук состояния.
2. `""` — начальный пустой запрос.
3. `filter` — выбирает подходящие элементы.
4. `query` — управляемое значение input.
5. `value` — текущий текст из поля.
6. `length` — число результатов.

Поиск идёт по названию, стране, городу и описанию. Пример: `  ПАРИЖ  ` → 1 путешествие. Запрос `прогулки`, категория «Город», сортировка по бюджету → 3 поездки: Тбилиси, Стамбул, Париж.

## Таблица 7.1: состояние страницы

| State | Начальное значение | Компонент | Влияние |
| --- | --- | --- | --- |
| query | `""` | SearchBar | Фильтрует по тексту |
| category | `"all"` | CategoryFilter | Выбирает формат отдыха |
| sort | `"default"` | SortSelect | Меняет порядок копии списка |

State находится в `TripsPage`. Кнопка «Сбросить» возвращает все три начальных значения. `visible` не хранится в state.

## Шаг 8: главная

Название подборки: «Ближайшие путешествия». Правило: `sortTrips(trips, 'date').slice(0, 3)`. Это 3 самые ранние поездки из демонстрационного массива, а не динамическая фильтрация относительно текущей даты. Для главной и списка используется один TripList.

## Контрольные вопросы — пояснения по коду

1. Props приходят от родителя и не изменяются дочерним компонентом. State — локальные данные, обновление которых вызывает отрисовку.
2. Стабильный `key={trip.id}` позволяет React сопоставить карточки после поиска и сортировки. Индекс массива меняется вместе с порядком.
3. Управляемое поле получает `value={query}` и меняет state через `onChange={(e) => setQuery(e.target.value)}`.
4. Видимый список полностью определяется исходными поездками, запросом, категорией и сортировкой. Отдельный state создал бы необходимость синхронизировать одни и те же данные.
5. `sort()` меняет исходный массив. `[...trips].sort(...)` сохраняет исходный порядок для режима «По умолчанию».
6. Подъём состояния — хранение данных в общем родителе. SearchBar передаёт новое значение странице, которой оно нужно для расчёта списка.
7. `useParams()` возвращает строки, а ID в данных — числа. Перед строгим сравнением используется `Number(tripId)`.
